ПРОМТ ДЛЯ НОВОГО ЧАТА — BotControl (скопируй всё ниже линии и вставь первым сообщением)
==========================================================================================

Продолжаем проект BotControl: Android-приложение на Kotlin и Jetpack Compose
(пакет com.botcontrol.admin). Оно превращает телефон в хост локальных
Telegram-ботов: long polling Bot API, несколько ботов на разных токенах,
правила и кнопки, анимации правкой сообщения, фото-анимации, расписание и
посты в канал, режим «Объявления», импорт и экспорт конфигов ботов «кодом»
(python-подобный текст, который НЕ исполняется), LLM строго на устройстве.

ПЕРВЫЕ ДЕЙСТВИЯ (по порядку):
1. Подтяни проект в свою ветку сессии (у нового чата будет своя ветка arena/…):
     git fetch origin arena/01a0d2d9-oracle main
     git merge --ff-only FETCH_HEAD   # или: git reset --hard origin/arena/01a0d2d9-oracle,
                                      # если в твоей ветке только «Initial commit»
   Если PR #1 уже влит, достаточно origin/main.
   Проверь: git log --oneline -3 (последние коммиты — «docs: v1.6.5 доставлен» или новее).
   Удобная ссылка: ln -sfn "$PWD/tg-bot-control" /home/user/tg-bot-control
2. Прочитай ЦЕЛИКОМ:
     handoff/01-project-rules.txt     — мои строгие требования (соблюдать всегда)
     handoff/02-build-release.txt     — сборка APK в GitHub Actions, проверка, ссылки
     handoff/03-sandbox-traps.txt     — ловушки песочницы и кода (что уже ломалось)
     handoff/04-state-and-backlog.txt — текущее состояние, карта файлов, открытые задачи
     tg-bot-control/ПЕРЕДАЧА-КОНТЕКСТА.md — полная память проекта (грамматика импорта,
                                          история версий, ловушки)
3. Проверь, что CI сработает на твоей ветке: в .github/workflows/*.yml
   стоит branches: ["arena/**", "main"]. Сборка APK запускается пушем в ветку,
   тег и релиз создаются, когда в сообщении коммита есть [apk].

ПОСЛЕДНЕЕ, ЧТО ДЕЛАЛИ (v1.6.3–v1.6.5): изоляция ботов. Уточняющие вопросы,
запасной ответ и кулдаун одного бота звучали во всех, потому что в
LocalBotStore botId = -1 означает «активный в UI бот». Теперь в service/ и
data/ botId передаётся явно, это проверяет CI-скрипт
tg-bot-control/tools/check-bot-isolation.py. Ещё добавлены: владелец у наборов
ответов, метка [@бот] в журнале, подтверждение всех удалений, параметры ИИ
своего бота на каждый запрос, версия в строке «🚀 Бот запущен».
ВАЖНО: если я пришлю лог без меток [@бот] и без «· BotControl vX» в строке
запуска, значит, он снят на старой сборке (≤ v1.6.2). Сначала скажи мне
об этом, не ищи заново уже исправленную ошибку.
