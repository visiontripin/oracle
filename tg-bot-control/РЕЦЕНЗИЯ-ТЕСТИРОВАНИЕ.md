# Рецензия по результатам тестирования BotControl
### Android-приложение и Windows-версия (desktop-web)

**Роль:** QA-инженер / бета-тестер (обозреватель ПО)
**Дата тестирования:** 9 ноября 2026 г.
**Ветка:** `arena/c6955075-oracle`
**Протестированные сборки:**
- Android: исходники v1.7.1 (versionCode 34, «тестовая сборка») — текущее состояние ветки;
- Windows (desktop-web): `tg-bot-control/desktop-web/` на Python 3.11 (эквивалент сборки `BotControl.exe` из GitHub Actions «BotControl Windows»).

---

## 0. Резюме в двух словах

Идея «телефон = хост Telegram-ботов, без сервера» реализована сильно: мультиботы,
изоляция настроек, анимации, расписание, импорт/экспорт конфигов «кодом»,
ИИ строго на устройстве. Автотесты зелёные, импортёр эталонных конфигов
разбирает без единого замечания. Но у обеих версий есть воспроизведённые баги
(в Windows — потеря входящих сообщений при сбое отправки и «замок» запуска
после остановки), серьёзные неудобства (Windows: один бот и данные в браузере;
Android: только debug-APK, нет автозапуска после перезагрузки) и заметный
разрыв функций между платформами. Ниже — подробно, с фактами и предложениями.

## 2. Рецензия: Android-версия (от лица пользователя)

### 2.1 Что нравится (честно)

1. **Мультиботы работают как обещано.** После v1.6.3 каждый бот отвечает
   своими настройками, в журнале видна метка `[@бот]` и версия сборки —
   диагностика «кто именно ответил» стала удобной. CI-страж (`check-bot-isolation.py`)
   реально защищает от регрессии — проверено.
2. **Импорт конфигов «кодом» — сильная сторона.** Прогнал эталонный перекур-бот:
   расписание (13 событий, включая пятничное «до завтра!»), перекурные кнопки,
   наборы, кулдаун 10 с, typing 4 с, характер Смита — всё разобрано идеально,
   без замечаний. Круг «импорт → экспорт → импорт» без потерь.
3. **Всё подтверждениями.** Удаления правил, кнопок, наборов, моделей —
   везде диалог подтверждения (правило соблюдено).
4. **Имитация бота** («раздумья»: какое правило сработало) — отличный способ
   отладить бота без Telegram.
5. **ИИ строго на устройстве**, по умолчанию выключен, отвечает только по
   `/chat` и явным правилам — правильный баланс «функции — кодом, творчество — ИИ».
6. **Анимации (10 шаблонов + свои кадры + фото-кадры)** — уникальная фишка,
   на телефоне работает через правку одного сообщения.

### 2.3 Неудобства и затруднения в использовании

- **Первый запуск — квест**: скачать APK с GitHub (не Play), разрешить установку,
  создать бота в @BotFather, вставить токен, скачать .litertlm-модель для ИИ
  (гигабайты, руками, без встроенного магазина моделей). Для не-технического
  пользователя это 30–60 минут и три источника инструкций.
- **После ребута телефона бота надо поднимать руками** (A2/A3) — для «телефон как
  хост» это ключевой сценарий, а он не автоматизирован.
- **Обновление**: debug-сборка ставится поверх (сохраняя ботов — хорошо), но
  «скачать новый APK из релиза и установить» каждый раз — ручная рутина, автообновления нет.
- **Импорт чужого конфига** без понимания грамматики превращается в чтение
  `Инструкция-код-бота.md` (не в приложении, а в репозитории).
- **Проверка напоминаний**: чтобы понять, сработает ли расписание, надо ждать
  реального времени (имитация расписания не проигрывает).

### 2.4 Предложения по Android (по убыванию пользы)

1. **Автозапуск и живучесть**: receiver на `BOOT_COMPLETED` (+ `QUICKBOOT_POWERON`),
   запрос «не оптимимизировать батарею» при первом запуске бота, `SCHEDULE_EXACT_ALARM`
   для напоминаний, уведомление-статус с кнопками «Запустить все/Остановить все».
2. **Release-сборка и доставка**: подписанная release-сборка (хотя бы APK с
   инструкцией + sha256), per-ABI split или App Bundle — 98 МБ это много;
   встроенный экран «Обновления» со ссылкой на последний релиз GitHub.
3. **Мастер первого запуска**: пошаговый wizard «создай бота → вставь токен →
   выбери готовый сценарий (приветствие/FAQ/анекдоты) → запусти» прямо в приложении
   (сейчас есть промт и подсказки, но нет шагов).
4. **Импорт .py с предпросмотром**: показывать «что будет добавлено/изменено»
   списком и кнопкой «Проверить бота имитацией» до применения; предупреждения —
   красным списком, а не строкой внизу. Добавить режим «импорт в нового бота»,
   чтобы не перезаписывать текущего.
5. **Параметры ИИ**: для движков, не поддерживающих сэмплер — выключать/серить
   ползунки с подписью «движок LiteRT-LM задаёт свои значения», чтобы не обманывать.
6. **Журнал**: фильтр по боту, поиск, экспорт в файл, кнопка «поделиться логом»
   (диагностика по логам — уже часть рабочего процесса проекта).
7. **Имитация расписания**: кнопка «Проиграть событие сейчас» у каждого события
   расписания (с подтверждением) — проверка без ожидания.
8. **Документация в приложении**: вкладка FAQ с `Инструкция-код-бота.md` и
   чек-листом проблем (они уже написаны — осталось встроить).
9. Свести README/handoff к актуальной версии (A9).

## 3. Рецензия: Windows-версия (desktop-web → BotControl.exe)

### 3.1 Что нравится

1. **Запуск в один клик**: `Start-BotControl.cmd` / `BotControl.exe` поднимает
   локальный сервер и открывает браузер. Python для .exe не нужен.
2. **Валидация и русские ошибки** на всех формах («Укажите время ЧЧ:ММ»,
   «Названия кнопок должны быть уникальными», «Команда должна начинаться с /…») —
   проверено живьём, сообщения понятные.
3. **Безопасность продумана**: токен только в памяти, не экспортируется и не
   попадает в `.bc`; проверено тестом — токен в ошибке не утекает; импорт
   запрещает поля `token`, `script`; Origin/Host-проверка от CSRF и чужих
   вкладок; запрет публичного bind. Импортированные файлы не исполняются.
4. **«Проверить сценарий» (симуляция)** — быстро и удобно, показывает результат
   без Telegram.
5. **Генерация бота через LLM** с готовым промптом и безопасным импортом JSON —
   удачный мост для новичков.
6. Тесты покрывают рантайм прилично (18 сценариев, включая «токен не утекает»,
   публичный bind, дубли кнопок).

### 3.2 Ошибки (воспроизведены!)

| # | Серьёзность | Проблема | Как воспроизвести / факты |
|---|---|---|---|
| W1 | **критическая** | **Падение sendMessage «съедает» остальные входящие сообщения пакета.** Если ответ одному пользователю не удался (заблокировал бота, запретил сообщения — 403), сообщения остальных чатов из того же пакета getUpdates **теряются навсегда** (offset уже сдвинут), а в интерфейсе висит ложное «Ошибка связи с Telegram» | Воспроизведено мок-тестом: в пакете 3 сообщения, падение на 2-м → отвечен только чат 1, чат 3 пропал. `server.py`, цикл `for update in updates` без try/except на сообщение |
| W2 | **высокая** | **«Запустить» заблокирован после «Остановить» до ~20 с.** Long-poll `getUpdates` (timeout=20) не прерывается, состояние «Остановка…», кнопка «Запустить бота» disabled, программный повторный старт отклоняется: «Бот уже запущен или останавливается» | Воспроизведено: остановка → мгновенный запуск отклонён, доступен только через ~6–20 с. `Runtime.stop()/start()` |
| W3 | **средняя** | **`http://localhost:8765/` → 403 Forbidden без объяснения.** Проверка Host жёстко требует `127.0.0.1:8765`; пользователь, введший «localhost» (или зашедший по имени компьютера), получает пустую 403-страницу | Воспроизведено curl: Host `127.0.0.1:8765` → 200; Host `localhost:8765` → 403. `Handler.valid_host()` |
| W4 | **средняя** | **Ложное «Ошибка связи с Telegram»**: любое исключение в цикле обработки (включая сбой отправки одному чату, W1) помечает ошибкой связи, хотя опрос работает. Реальная причина (403, 429, «chat not found») не показывается — описание ошибки Telegram отбрасывается | `run()`: общий `except Exception` → фиксированная строка |
| W5 | **средняя** | **Фразы-триггеры срабатывают по подстроке без границ слова**: фраза «кот» срабатывает на «ско**т** и стадо», «привет» — на «приветствую» | Воспроизведено через `/api/simulate`. `match_action()` — `value in text.casefold()` |
| W6 | **средняя** | **«Не удалось подключить бота. Проверьте токен и интернет»** — одна фраза и для неверного токена, и для отсутствия сети. Telegram возвращает точную причину (401 Unauthorized и т.п.), но она не парсится | Воспроизведено с мусорным токеном. `Runtime.run()`, `telegram()` |
| W7 | **низкая** | **«Наборы из Android .py» подтягивает мусор**: из `smith-bot-ready.py` извлекается `ANIM_START` (кадры анимации), из `presentation-bot-ready.py` — `INTRO_FRAMES` с записями `photo: https://…`. Пользователь получит «ответы» вида `photo: …`. В диалоге предупреждено только про НЕпереносимое, но не про то, что часть списков — вовсе не ответы | Воспроизведено на реальных конфигах через `/api/import-python` |
| W8 | **низкая** | **Напоминания: минута = единственная попытка.** Совпадение строго по `ЧЧ:ММ` при тике 5 с; пропустил минуту (загрузка CPU, сон) — событие потеряно до следующего дня; сбой отправки помечает событие отправленным без повтора | `schedule_loop()`: `sent[index]` ставится ДО успешной отправки; в README честно сказано «пропущенные не воспроизводятся» — но это всё же слабое место |

### 3.3 Неудобства и затруднения

- **Один бот вместо нескольких** (у Android — сколько угодно): переключение
  между ботами = импорт/экспорт `.bc` и перезапуск. Для владельца нескольких
  ботов (как у заказчика: презентация, объявления, оракул) — главный камень преткновения.
- **Данные редактора — в localStorage браузера**, привязаны к адресу:порту.
  Случайный запуск на другом порту / другой браузер = «пропали мои боты»
  (спасает только `.bc`, о чём надо было думать заранее). Реальных инцидентов
  потери данных не избежать.
- **Токен вводится заново после каждого перезапуска** (безопасность — правильно,
  но при ежедневном использовании утомляет).
- **После каждого правления конфигом нужен ручной перезапуск бота**
  («Остановить» → ждать до 20 с (W2) → «Запустить» → вставить токен). Одна кнопка
  «Перезапустить» уже убрала бы половину боли.
- **Журнал без текста сообщений и без имён сценариев** — «найден сценарий», но
  какой? Для отладки триггеров приходится гадать. Chat ID для напоминаний ищут
  вручную в этом же журнале.
- **Консольное окно надо держать открытым** — закрыл окно = бот умер (документировано, но новичок не догадается).
- **Занятый порт 8765**: ошибка на английском (`Cannot start server: …`), без
  подсказки «закройте старый экземпляр»; самовольный `--port 8766` — ловушка,
  т.к. хранилище привязано к порту.
- **LAN-режим без авторизации и HTTPS** — только предупреждение в консоли.
- **`.bc` несовместим с Android** — конфиги между платформами не переносятся,
  кроме вырезки текстовых списков (W7).

### 3.4 Предложения по Windows-версии

1. **Исправить W1 (критично)**: оборачивать обработку каждого `update` в
   try/except, логировать сбой отправки с конкретным chat ID и продолжать пакет;
   offset двигать только после обработки (или держать очередь повторов).
2. **Исправить W2**: прерывать long-poll при остановке (отмена запроса / короткий
   timeout + частый опрос stop_event), либо кнопка «Перезапустить» = stop+start
   одной операцией, с ожиданием внутри сервера.
3. **Исправить W3**: принимать `Host` `localhost:*`, `127.0.0.1:*`, `[::1]:*`
   (или отдавать дружелюбную страницу-объяснение вместо 403).
4. **Исправить W4/W6**: разбирать ответ Telegram (`description`, код 401/403/429)
   и показывать конкретную причину; делить «ошибка опроса» и «ошибка отправки».
5. **Исправить W5**: сопоставление фраз по словам (границы слова), либо чекбокс
   «совпадение по подстроке» в настройках сценария.
6. **Мультиботы**: как минимум — список конфигов и быстрое переключение
   (несколько рантайм-слотов по токенам), как максимум — паритет с Android.
7. **Хранение данных**: автосохранение `.bc` на диск (папка `BotControl/backups`
   с ротацией), предупреждение при старте, если localStorage пуст, а бэкапы есть;
   опционально — токен в Windows Credential Manager.
8. **Журнал**: имя сценария/команды в строке лога, кнопка «/chatid» (последние
   чаты с ID), фильтр.
9. **W7**: фильтровать `ANIM_*`/`*_FRAMES`/`photo:` при импорте списков или
   помечать их в диалоге с превью первого элемента.
10. **W8**: окно допуска «в течение N минут после указанного времени» + одна
    повторная попытка при сбое.
11. **Мелочи**: локализовать ошибку занятого порта + автоподсказка; подпись
    Windows-сборки (или подробная инструкция с хешем — она уже есть, но внутри
    README, а нужна рядом с .exe).

|---|---|---|---|

| P1 | Обе | Сближение форматов/функций (мультиботы и `.py`-импорт на Windows) | Одинаковый сценарий на обеих платформах |
| P2 | Android | A1 — release-доставка, размер APK | Доверие и установка новичками |
| P2 | Обе | UX импорта/журнала/напоминаний (A4, A7, A8, W5, W7, W8) | Меньше ошибок пользователей |

## 5. Общий вердикт

**Рекомендую к использованию с оговорками.** Android-версия — зрелый продукт
с сильной архитектурой (мультиботы, изоляция, импорт «кодом», ИИ на устройстве);
ей не хватает «бытовых» вещей: release-сборки, автозапуска и мастера первого
запуска. Windows-версия — удобный локальный редактор и неплохой запускатель
одного бота, но как продукт она пока «предварительная»: критичный баг потери
сообщений (W1), замок перезапуска (W2) и данные в браузере требуют исправления
до рекомендации широкому кругу. Автотесты и качество инженерии — на высоте:
все 70+ проверок зелёные, импортёр и экспортёр безупречны на эталонах; база для
быстрых исправлений отличная.
