# «Даром в ПЛ»: перенос в приложение + фичи

## 1. Что перенесено в `daromvpl-bot-ready.py` (импортируется 1:1)

| В оригинале (python-telegram-bot) | В конфиге приложения |
|---|---|
| `start()`, справка, `/rules`-логика в текстах | Правила-команды /start, /help, /rules с полными текстами |
| Шаблон caption «📦 Отдам даром…» | Характер ИИ-редактора: собирает пост по формату (📦/🏙/✨/🚗 + контакт) |
| Антифлуд `time.time() - last < 60` | `ANSWER_COOLDOWN = 60` (пауза между ответами) |
| PHONE_REGEX и вопросы уточнения | `CLARIFY_QUESTIONS` — 6 вопросов (что/город/состояние/самовывоз/фото/контакт) |
| Реакции «Отдано/занято/спасибо» (в коде не было текстов) | Наборы TAKEN_LINES / BUSY_LINES / THANKS_LINES |
| Ротация логов, RetryAfter-паузы | Встроено в приложение: 📜 Журнал событий, автопауза при 429 |
| `drop_pending_updates=True` | Встроено: сервис подтверждает накопленные апдейты при старте |

## 2. Ручные шаги после импорта (по 3 клика)

1. **Клавиатура** (Настройки бота → Клавиатура): `📝 Разместить объявление`, `📋 Мои объявления`, `❌ Отмена`.
2. **Правила** (Правила → + правило, тип «содержит»):
   - `отдано` → действие «набор» → TAKEN_LINES
   - `занято` → действие «набор» → BUSY_LINES
   - `спасибо` → действие «набор» → THANKS_LINES
3. **▶ Запустить бота**, в Telegram /start, для дайджеста — кнопка ▶️ (или включи напоминания в карточке).

## 3. Что непереносимо 1:1 и почему (архитектура оригинала)

- **ConversationHandler (6 состояний)** — пошаговый визард: приложение пока отвечает на каждое сообщение отдельно; состояние диалога хранит ИИ-память (4 реплики), но не «корзину фото».
- **aiosqlite-база объявлений** — у приложения нет своей таблицы объявлений; роль «моих объявлений» выполняет история чата.
- **Публикация фото в канал @daromvpl** — send_photo/send_media_group в канал, где бот админ; приложение умеет слать текст и inline-кнопки, фото не принимает и не пересылает.
- **URL-кнопка «✉️ Написать автору» (tg://user?id=…)** — в InlineBtn сейчас только callback-действия, url-кнопок нет.
- **OWNER_ID-модерация** — уведомление админу со ссылками и кнопкой удаления; требует адресата «админ» и deeplink-ссылок на сообщения.
- **/myid** — показывает Telegram ID; в правилах приложения нет плейсхолдера ID (есть {user} = имя).

## 4. Фичи, уже работающие в этой конфигурации

1. **ИИ-редактор постов**: прислал описание → получил готовый пост по формату канала; не хватает данных — задаёт один уточняющий вопрос.
2. **Антиспам 60 с** — как в оригинале, настраивается в «Поведение и паузы».
3. **Дайджест-расписание**: утро/вечер ежедневно + будничный «подними объявления».
4. **Наборы реакций** для коротких слов («отдано», «занято», «спасибо») — живой тон бота.
5. **/rules** — правила канала всегда под рукой, меньше нарушений.

## 5. Дорожная карта приложения (чтобы покрыть бота полностью)

**P0 — максимальный эффект:**
- **URL-кнопки** в inline-меню (действие `url`): «Написать автору», ссылки на канал — открывает сценарии продаж/контактов.
- **Плейсхолдеры `{chat_id}` / `{username}`** в текстах правил — вернёт функцию /myid и подпись автора в постах.
- **Пошаговые визарды** в правилах: цепочка «вопрос → ответ → вопрос» с корзиной данных и финальным предпросмотром.

**P1 — публикация в канал:**
- Событие/правило с адресатом «канал» (bot = админ канала, шлём текст в @канал) — постинг объявлений из чата.
- Приём фото от пользователя (media в правилах, до N штук) + подпись к ним.
- Мини-БД объявлений per-bot: сохранить / мои / переопубликовать / удалить.

**P2 — модерация и надёжность:**
- Роль «админ бота» (ID из карточки) + уведомления админу с deeplink на сообщения.
- Лимит публикаций per-user, валидация ввода (маска телефона) в визардах.
- Кнопка «Удалить из канала» у уведомления модерации.

## 6. ⚠️ Безопасность (сделай сразу)

В присланном коде **настоящий токен бота** (и в первом боте тоже). Он попал в чат/файлы —
считай скомпрометированным: **BotFather → /mybots → бота → API Token → Revoke**, новый токен
вставляй только в приложение (он хранится в EncryptedSharedPreferences и в экспорт не попадает).
