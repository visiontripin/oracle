## 1. Что за проект

**BotControl** — Android-приложение (Kotlin + Jetpack Compose, пакет
`com.botcontrol.admin`), которое превращает телефон в хост локальных
Telegram-ботов:,long polling через Telegram Bot API, LLM **строго на
устройстве** (LiteRT-LM / MediaPipe, .litertlm модели, без облака),
мультиботы на разных токенах, всё настраивается кнопками в приложении.

Плюс формат «конфигов кодом»: настройки бота описываются python-подобным
текстом и импортируются/экспортируются приложением (это транспортный
формат, код НЕ исполняется).

Есть также серверная часть (FastAPI + aiogram3) в задумке, но активно
разрабатывался только Android-клиент (local mode).

## 4. Как собирать и доставлять APK

**В песочнице агента собрать нельзя:** закрыты `dl.google.com`,
`maven.google.com`, Maven Central и `services.gradle.org` — ни Android SDK,
ни AGP/Compose/Room не скачать. JDK и компилятор Kotlin при желании
поднимаются из PyPI (`pip install jdk4py kotlin-jupyter-kernel` — внутри
есть `org.jetbrains.kotlin.cli.jvm.K2JVMCompiler`), но Android-зависимостей
всё равно нет. Поэтому APK собирается в GitHub Actions.

```bash
# 1) bump версии в android/app/build.gradle.kts (СНАЧАЛА!)
#    versionCode = 23, versionName = "1.5.3"
# 2) баланс скобок после правок .kt (strip-strings сканер) + вычитка импортов
# 3) коммит с [apk] в сообщении → воркфлоу соберёт, проверит aapt,
#    выложит артефакт и pre-release с APK:
git add -A && git commit -m "Что сделано [apk]"
git push origin arena/01a0d2d9-oracle
# 4) статус и результат:
gh run list -R visiontripin/oracle --limit 3
#    аннотации (в т.ч. строка aapt dump badging) — тут:
gh api repos/visiontripin/oracle/check-runs/<JOB_ID>/annotations
# 5) APK забрать из тега релиза (release-assets и blob артефактов
#    в песочнице НЕДОСТУПНЫ — gh release download / gh run download падают
#    с EOF, работает только через git):
git fetch origin refs/tags/botcontrol-v1.5.2-code22
git show botcontrol-v1.5.2-code22:tg-bot-control/BotControl-debug.apk \
  > tg-bot-control/BotControl-debug.apk
#    проверка:
python3 -c "import pyaxmlparser,sys; a=pyaxmlparser.APK(sys.argv[1]); \
print(a.packagename, a.version_code, a.version_name)" tg-bot-control/BotControl-debug.apk
# 6) очистка build-каталогов (иначе раздувается workspace):
rm -rf tg-bot-control/android/app/build tg-bot-control/android/.gradle
# 7) present_file(tg-bot-control/BotControl-debug.apk) + сводка
```

Воркфлоу: `.github/workflows/botcontrol-apk.yml` (пуш в ветку сессии,
`paths: tg-bot-control/android/**`). Собирает `gradle :app:assembleDebug`,
печатает `aapt dump badging` аннотацией, загружает артефакт
`BotControl-debug-apk` и (при `[apk]` в сообщении коммита) делает тег
`botcontrol-v<версия>-code<код>` + pre-release с APK.

**Подпись:** в `android/app/build.gradle.kts` задан постоянный debug-ключ
`android/app/debug.keystore` (пароль `android`, alias `androiddebugkey`).
Благодаря ему APK из CI ставится поверх установленного, без удаления
приложения и потери ботов. Ключ лежит в репозитории — это debug-сборка.

Локальная проверка Kotlin без Android (пригодилась для импортёра):
`jdk4py` + `kotlin-jupyter-kernel` дают `K2JVMCompiler`; файлы
`data/PySource.kt`, `data/ScriptImporter.kt`, `data/SettingsExporter.kt`,
`data/BotExtras.kt` компилируются и прогоняются на реальных конфигах
(оракул, bot-config-ready.py, demo-конфиг) без участия Android SDK.
Готовый харнесс лежит в репозитории: **`tools/kotlin-harness/`**
(`kc.sh` — компиляция, `run.sh` — запуск, `src/Dump.kt` — печать разбора,
`stubs/`, `stubs2/` — заглушки вместо Android/Gson) и конфиги-фикстуры в
`tools/import-fixtures/` с эталонными цифрами. Прогонять при каждой
правке импортёра: изменился вывод или появился warning — значит регрессия.

## 5. Грамматика импорта (PySource + ScriptImporter, v1.5.2)

Импорт больше не «регэксп по файлу»: `PySource` разбирает структуру
(строки, комментарии, логические строки, отступы, функции, выражения),
а `ScriptImporter` превращает её в настройки. Подробная таблица
блоков — в **`Инструкция-код-бота.md`** (раздел 2), здесь — суть:

- **Команды:** `@bot.message_handler(commands=["start"])` + `def cmd_start`;
  текст ответа — из `send_message` (до `reply_markup`).
- **Правила на текст:** `func=lambda m: m.text == "…"` → тип «Кнопка»;
  `"фраза" in (m.text or "").lower()` → «Содержит»; `Text(equals=…)` и
  `regexp="простой текст"` тоже понимаются.
- **Inline-меню:** функции с `InlineKeyboardMarkup` / `InlineKeyboardBuilder`;
  `markup.row(...)`, `.add(...)`, `.insert(...)`, `.adjust(2, 1)`,
  `inline_keyboard=[[…]]` — ряды сохраняются в поле `InlineBtn.row`.
  `url="…"` → кнопка-ссылка.
- **Обработчик нажатий:** `@bot.callback_query_handler` (общий или с
  фильтром `call.data == "…"`) и/или ветки `if/elif call.data == "…"`,
  `match/case`. Внутри понимаются:
  `answer_callback_query` → всплывашка (перед `return` — ответ на повторное
  нажатие); `send_message` → новое сообщение; `edit_message_text` → правка
  сообщения под кнопкой; `random.choice(НАБОР)` → действие «набор»
  (и `def get_joke(): return random.choice(JOKES)`); присваивание
  `bot_running = True/False` (или любой переменной из `remind|run|active|…`)
  → кнопка включает/выключает напоминания.
- **Клавиатура чата:** `ReplyKeyboardMarkup` + `KeyboardButton`, прикреплённая
  `reply_markup=chat_keyboard()` (приоритет у /start).
- **Наборы:** `ИМЯ = [ "…", ]` — закрывающая `]` на отдельной строке;
  комментарий на строке `ИМЯ = [` становится названием набора.
- **Расписание:** кортежи в `get_today_schedule(now)`; 4-й элемент —
  меню под напоминанием; зоны дней — любые `if/elif/else` по
  `wd` / `weekday()` / `isoweekday()`, включая `in (5, 6)` и диапазоны.
  `»канал` в начале текста → в канал; варианты `" | "` → ротация по дням.
- **Прочее:** `bot.set_my_commands([...])` → меню Telegram;
  `CHANNEL_ID`, `LISTINGS_MODE` → настройки канала и объявлений.
- **Замечания:** всё, что понять не удалось (кнопка без обработчика, меню
  без `reply_markup`, набор по ссылке без списка, слишком сложный фильтр),
  попадает в `Parsed.warnings` и показывается на экране импорта.

## 7. Требования пользователя (соблюдать СТРОГО)

1. **Палитра Telegram:** background #0E1621; surface/контейнеры #17212B;
   surfaceVariant #182533; primaryContainer #2B5278; primary #5288C1;
   текст #F5F6F7; вторичный текст #7F91A4; tertiary #FBBF24; outline #33475A.
   **Тёмного текста быть не должно** — `lightTypography()` задаёт F5F6F7
   всем 15 стилям. Edge-to-edge (тёмные системные панели, светлые иконки),
   NavHost в `Box(statusBarsPadding)`.
2. **Всё настройка кнопками/списками/диалогами**; редактор кода только для
   нестандартной JS-логики. Никакого экрана логина в local mode.
3. **Безопасность:** токены в EncryptedSharedPreferences (`token_$id`),
   в экспорт не попадают; никаких публичных эндпоинтов; файловый сервер —
   только вручную, локальная сеть; arbitrary exec запрещён (Rhino с
   ClassShutter, optimizationLevel -1).
4. **LLM только локально на телефоне**, без облака.
5. Мультиботы: настройки строго изолированы per-bot (botId в ключах).
6. Оракл — рабочий python-бот (`uploads/oracle code.txt`): импортированный
   бот обязан вести себя как оригинал (расписание будни+пятница, /start с
   кнопками Запуск/Стоп, перекурные кнопки, SYSTEM_PROMPT Смита,
   cooldown 10с, typing 4с, память 4).
7. Каждая итерация = **готовый APK** + понятная сводка; версия бампается.
8. Удаление ботов/настроек — с подтверждением. «Запустить/Остановить» —
   только конкретный бот, «Все боты» — отдельные кнопки.
9. Новые библиотеки — только проверенные (Maven Central HTTP 200), без
   выдуманных.

## 8. Технические ловушки (проверено на ошибках)

- **bash-инструмент:** `cwd` — только чистый путь; `cd` первой строкой
  `command`. Долгие сборки — через `start_process` + полл `/tmp/build.log`.
- **python-хередок ↔ Kotlin:** `\n` в python-строке становится переводом
  строки — замену Kotlin-строк с `\n` делать через raw-строки python
  `r'...'`; `"""` внутри хередока запрещён (использовать `'''…'''`);
  `$var` в Kotlin-шаблонах экранировать (`$min_` → `${min}`).
- Kotlin regex в коде писать только raw-строками `"""…"""`.
- Добавил `LaunchedEffect`/компонент — **проверь импорты** в файле
  (частая причина падения сборки).
- `Result.success(...)` явно оборачивать внутри fold/parse-лямбд (вывод
  типов ломается); `onSuccess` у `sendMessage` возвращает Unit — не ждать id.
- Elvis внутри `states.value + (id to x?.copy() ?: Y)` не компилируется —
  вычислять до; suspend-вызовы из лямбд — выносить.
- После правок гонять strip-strings баланс-сканер скобок по всем .kt.
- Незакрытый `Column`/скобка в диалогах AlertDialog — проверять хвост
  файла после вставки секций.
- Безвредные артефакты (не чинить): дубль `topK = it` в AiSettingsScreen;
  мёртвый regex-префикс в ScriptImporter.parse.
- Ошибки сборки обычно 0–2 цикла фиксов; после успеха — очистка build-каталогов.

## 12. Если workspace пуст (новая песочница)

Попроси пользователя загрузить `botcontrol-handoff.zip` и распакуй:
```bash
cd /home/user && python3 -c "import zipfile; zipfile.ZipFile('botcontrol-handoff.zip').extractall('/')"
```
Затем: сборка по разделу 4 (скрипт сам поставит JDK/SDK). Ораклы лежат в
`uploads/` архива.

**Первое действие в новом диалоге:** прочитать этот файл, затем
`ls /home/user/tg-bot-control`, проверить версию APK (aapt) и спросить
пользователя задачу, если её не дали в первом сообщении.

## 13. Git — единственный источник истины

Весь проект живёт в репозитории **https://github.com/visiontripin/oracle**
(ветка сессии `arena/01a0d2d9-oracle`). Всё, что должно пережить диалог,
коммитится и пушится туда: исходники, конфиги, доки, воркфлоу,
`tools/`-харнесс и фикстуры. APK — в тегах релизов
(`botcontrol-v<версия>-code<код>`), сам файл в gitignore.

**Никогда не коммитить:** живые токены ботов (они встречаются в ораклах из
`uploads/`) и любые ключи, кроме debug-keystore.
