# ПЕРЕДАЧА КОНТЕКСТА: проект BotControl

Память проекта для нового диалога. Сначала прочитай этот файл и
`handoff/00-PROMPT-new-chat.txt` … `handoff/04-state-and-backlog.txt`.

## 1. Что за проект

**BotControl** — Android-приложение (Kotlin + Jetpack Compose, пакет
`com.botcontrol.admin`), которое превращает телефон в хост Telegram-ботов:

- long polling Bot API, сколько угодно ботов на разных токенах;
- правила (команда / фраза / кнопка → текст, набор, JS-скрипт, анимация, ИИ);
- inline-кнопки, клавиатура чата, расписание и посты в канал;
- режим «Объявления» (визард → публикация в канал);
- LLM **только на устройстве** (MediaPipe GenAI / LiteRT-LM, без облака);
- конфиги ботов «кодом»: python-подобный текст импортируется и
  экспортируется, но **не исполняется** (это транспортный формат).

Серверной части (FastAPI + aiogram) в репозитории больше нет: она не
развивалась и удалена в v1.7.0. Экраны серверного режима в приложении
остались в коде как архив, но точки входа в них нет.

## 5. Грамматика импорта (кратко)

`PySource` разбирает структуру python-текста, `ScriptImporter` превращает
её в настройки. Полная таблица — `Инструкция-код-бота.md`, раздел 2.

- **Команды:** `@bot.message_handler(commands=["start"])` + текст из `send_message`.
- **Правила:** `m.text == "…"` → «Кнопка», `"фраза" in m.text.lower()` → «Содержит».
- **Меню:** функции с `InlineKeyboardMarkup`/`InlineKeyboardBuilder`, ряды
  сохраняются, `url="…"` → кнопка-ссылка.
- **Обработчик нажатий:** `answer_callback_query` → всплывашка,
  `send_message` → новое сообщение, `edit_message_text` → правка под кнопкой,
  `random.choice(НАБОР)` → действие «набор», `bot_running = True/False` →
  кнопка включает/выключает напоминания.
- **Клавиатура чата:** `ReplyKeyboardMarkup` + `KeyboardButton`.
- **Наборы:** `ИМЯ = [ … ]`, комментарий на строке `ИМЯ = [` становится названием.
- **Расписание:** кортежи в `get_today_schedule(now)`, 4-й элемент — меню;
  `»канал` в начале текста → пост в канал; варианты через `" | "` → ротация.
- **Анимации:** `play_animation(...)`, цикл правок в обработчике, `bot.send_dice(...)`.
- **Прочее:** `bot.set_my_commands`, `CHANNEL_ID`, `LISTINGS_ON`.
- Всё непонятое попадает в `Parsed.warnings` и показывается на экране импорта.

## 7. Требования пользователя (строго)

1. **Палитра Telegram:** #0E1621 фон, #17212B панели, #182533 variant,
   #2B5278 primaryContainer, #5288C1 primary, #F5F6F7 текст, #7F91A4
   вторичный, #FBBF24 акцент, #33475A линии. Тёмного текста быть не должно,
   edge-to-edge, NavHost в `Box(statusBarsPadding)`.
2. Всё настраивается кнопками/списками/диалогами; редактор кода — только
   для нестандартной JS-логики.
3. Безопасность: токены в EncryptedSharedPreferences (`token_$id`), в
   экспорт и логи не попадают; файловый сервер только вручную и в локальной
   сети; произвольное исполнение кода запрещено.
4. LLM только на телефоне, без облака.
5. Мультиботы: настройки строго изолированы per-bot.
6. Каждая итерация = готовый APK со следующим versionCode + сводка на русском.
7. Удаление — только с подтверждением.
8. Новые библиотеки — только реально существующие.

## 8. Технические ловушки

- **`botId = -1L` = «бот, активный в UI».** На экранах это нормально, но в
  `service/` и `data/` всегда передавай `botId` явно, иначе настройки одного
  бота утекают во все (баг v1.6.2). Карты ключуй `"$botId:$chatId"`.
  Проверка: `python3 tools/check-bot-isolation.py`.
- После правок .kt — баланс скобок strip-strings сканером и вычитка импортов
  (лишний/недостающий импорт — самая частая причина падения сборки).
- Kotlin-regex — только raw-строки.
- `Result.success(...)` явно оборачивать в fold/parse-лямбдах.
- Незакрытый `Column`/скобка в диалогах — проверять хвост файла.
- Фото-анимация по кнопке: `editMessageMedia` без `reply_markup` снимает
  клавиатуру — меню вешается на последний кадр (`tailMenu`).
- SVG → PNG в песочнице: `resvg_py` (cairosvg без libcairo не работает);
  в SVG рисуются только символы DejaVu, эмодзи — нет.
