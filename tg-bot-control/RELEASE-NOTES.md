# BotControl v1.6.3 (code 30)

## 🔒 Изоляция ботов: каждый бот отвечает только своими настройками

- **Главный фикс.** Уточняющие вопросы и запасной ответ одного бота больше
  не появляются в других ботах. Раньше «мозг» бота читал их без номера бота,
  то есть у бота, открытого в приложении: @OneDope_bot и @Daromvpl_bot
  спрашивали «Уточните ваш вопрос о функциях BotControl» от @AppBotcontrol_bot.
- **Пауза между ответами (кулдаун)** тоже своя у каждого бота: берётся из
  настроек бота и считается отдельно для пары «бот + чат». Раньше ответ
  одного бота заставлял молчать остальных, потому что в личке у всех
  ботов один и тот же номер чата.
- **Наборы ответов при импорте.** Импорт обновляет только наборы своего
  бота и никогда не перезаписывает одноимённый набор другого бота. Одинаковые
  имена констант (`FORTUNES` у двух ботов) получают разные id. У набора видно,
  чей он: «бот @name» или «общий». При удалении бота удаляются и его наборы.
- **Экспорт `.py`** содержит только наборы этого бота и общие наборы, которые
  не используют другие боты. Тексты чужих ботов в файл больше не попадают.
- **Журнал событий подписан:** у каждой строки есть метка бота, например
  «📩 [@OneDope_bot] Сообщение», «   • [@OneDope_bot] Проверяю правила (2)»,
  «💬 [@OneDope_bot] Источник», «🎞 [@AppBotcontrol_bot] Анимация» (раньше
  был номер `[3]`). Метку получают кнопки, объявления, напоминания и посты
  в канал.

## 🧹 Второстепенное

- **Удаление только после подтверждения** везде: правила, кнопки
  клавиатуры, события расписания, наборы и их ответы, уточняющие вопросы,
  скачанные модели ИИ, файлы сервера, привязки ИИ.
- **Имитация** («Проверка бота») действительно начинает с чистого
  контекста: память ИИ очищалась не у того бота.
- **Защита от повторения ошибки:** в CI перед сборкой запускается
  `tools/check-bot-isolation.py`. Сборка падает, если сервисный код читает
  настройку без номера бота. Тест `tools/kotlin-harness/isolation.sh`
  проверяет изоляцию наборов в экспорте и метки журнала.
- **Порядок в репозитории:** удалены устаревший `botcontrol-handoff.zip`
  (в нём был токен бота, его нужно отозвать через @BotFather `/revoke`),
  копия `ПЕРЕДАЧА-КОНТЕКСТА.md` в корне и неработающий вложенный workflow.
  Восстановление workspace теперь только из git.

# BotControl v1.6.1 (code 28)

## 🖼 Фото-анимация: картинка меняется в одном сообщении

Вторая половина «фишек» — через **editMessageMedia**: бот присылает фото
и дальше меняет в этом же сообщении картинку и подпись.

- **Фото-флипбук и квест с иллюстрациями:** в «🎞 Свои кадры» кадр с первой
  строкой `photo: ссылка` — картинка, ниже — подпись. Кадр без `photo:`
  меняет только подпись под той же картинкой («Слышишь шорох…»).
- **Кнопки в редакторе:** «🖼 Фото из галереи» (можно выбрать несколько —
  каждое станет кадром) и «🔗 По ссылке». Предпросмотр показывает саму картинку.
- Фото с телефона загружается в Telegram один раз, дальше бот использует
  его file_id — повторный показ быстрый.
- Квест по кнопкам: кнопка «Анимация» с галочкой «анимировать это же
  сообщение» меняет картинку прямо под кнопками. Если сообщение текстовое,
  а анимация — картинками (или наоборот), бот покажет её новым сообщением.
- Экспорт и импорт понимают фото-кадры; выгруженный `.py` проигрывает их
  сам (send_photo → edit_message_media / edit_message_caption).
- Промт для создания ботов — v5.1 (кадры-картинки).

# BotControl v1.6.0 (code 27)

## Фишки: анимация правкой одного сообщения

Бот присылает сообщение и каждые 0,5–3 с **правит его же** следующим
кадром (editMessageText), в конце — итоговый текст и кнопки.

- **10 готовых эффектов:** ⠋ спиннер, ▰ прогресс-бар, … точки, ⏳ обратный
  отсчёт, ⌨️ печатная машинка, 🟩 «Матрица», 🎰 слот-машина (итог —
  случайная фраза из набора), 🌕 фазы луны, 🕐 часы, ❤️ сердце.
- **🎞 Свои кадры:** ASCII-заставки, флипбук, текстовый квест, где
  картинка меняется по ходу истории. Кадры — через строку `---`,
  моноширинный шрифт для ASCII-арта, пустые строки сверху сохраняются.
- **Где настроить:** правило → «🎞 Анимация»; кнопка под сообщением →
  «Анимация» (галочка «анимировать это же сообщение» — кнопки остаются).
  Живой предпросмотр прямо в редакторе и в «Имитации».
- **Бережно к лимитам Telegram:** не чаще 1 правки в 0,5 с, до 60 кадров,
  при «429 Too Many Requests» бот ждёт и продолжает; одна анимация на чат.

## 🎲 Кубики Telegram

Анимированный эмодзи со случайным результатом: 🎲 🎯 🏀 ⚽ 🎳 🎰 —
действием правила или кнопки.

## Импорт / экспорт

- Импорт понимает `play_animation(...)`, цикл правок в обработчике и
  `bot.send_dice(...)`; `&lt;` и другие HTML-сущности; кнопки `start`/`stop`
  без обработчика → вкл/выкл напоминаний.
- Экспорт пишет **обработчик нажатий** — кнопки после повторного импорта
  работают; блок ИИ — только если ИИ у бота включён; переносы строк и
  названия наборов сохраняются; события выходных больше не становятся
  буднями. Проверено кругом «экспорт → импорт» на 8 конфигах.
- Правка правила «Скрипт JS» через диалог больше не стирает его код.
- Промт для создания ботов — v5 (анимации и кубики).
